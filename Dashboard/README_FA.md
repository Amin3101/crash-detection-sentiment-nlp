# CrashLens v3 — داشبورد ارائه پروژه Nexar

این نسخه بر اساس بازخورد جلسه با منتور تغییر کرده است. **صفحه Scored Video Explorer به‌طور کامل حذف شده** و Project Journey قدیمی به **Experiment Graph & Logs** تبدیل شده است.

## چه چیزی تغییر کرده؟

- یک **گراف چهارمسیره از تصمیم‌ها و آزمایش‌ها** اضافه شده است. مسیرها مستقل‌اند؛ این نمودار ادعا نمی‌کند همه گزارش‌ها یک روند زمانی متوالی را ثبت کرده‌اند.
- گراف در مجموع **۱۵ تصمیم یا نقطه آزمایش** را نشان می‌دهد: هشت مرحله پاک‌سازی/مدل Pre-event، سه مرحله Event-centered، سه مرحله مدل زمانی Alert-aware و یک آزمایش Full-video.
- برای هر تصمیم: تغییر انجام‌شده، تنظیمات گزارش‌شده، نتایج عددی، نوع ارزیابی (Validation، Test یا CV)، برداشت و محدودیت، و بخش مربوط از **متن اصلی لاگ** نمایش داده می‌شود.
- برای آزمایش‌هایی که منحنی ثبت‌شده دارند، می‌توان **نمودار Epoch-by-Epoch و جدول نتایج کامل آن اجرا** را همان‌جا دید.
- هر سه فایل `log.md`، `nexar_collision_model_experiments.md` و `nexar_model_experiment_log.md` با امکان مرور بخش‌به‌بخش و دانلود اصل فایل حفظ شده‌اند. `final.ipynb` هم به عنوان منبع مستقل Detection در دسترس است.
- ورود CSV پیش‌بینی‌های ذخیره‌شده از نوار کناری حذف شده و فقط در صفحه Error Analysis، به‌صورت اختیاری، قرار گرفته است.

## نحوه اجرا روی ویندوز

فایل `CrashLens_v3.zip` را Extract کن و وارد پوشه `CrashLens_v3` شو. نوار آدرس File Explorer را انتخاب کن، `cmd` بنویس و Enter بزن.

اگر محیط پایتون قبلی‌ات را در `C:\Users\User\.venv` ساخته‌ای:

```bat
C:\Users\User\.venv\Scripts\python.exe -m pip install -r requirements.txt --default-timeout=120 --retries=10
C:\Users\User\.venv\Scripts\python.exe -m streamlit run app.py
```

اگر محیط قبلی نداری:

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt --default-timeout=120 --retries=10
.venv\Scripts\python.exe -m streamlit run app.py
```

صفحه در `http://localhost:8501` باز می‌شود. اگر داشبورد v2 هنوز در حال اجراست، ابتدا در CMD قبلی `Ctrl+C` بزن.

## معرفی صفحات باقی‌مانده

1. **Overview:** خلاصه دو پروتکل Detection و Anticipation؛ نتایج مستقیم با هم قابل مقایسه نیستند.
2. **Run Two Models:** اجرای مدل روی ویدیوی آپلودشده فقط پس از اتصال وزن‌های اصلی مدل‌ها.
3. **Experiment Graph & Logs:** گراف مسیرهای مستقل، توضیح تنظیمات و نتایج هر گام، نمودار مربوط به همان اجرا، متن اصلی لاگ.
4. **Training History:** هر هفت اجرای دارای لاگ Epoch و مجموع ۶۸ Epoch.
5. **Model Lab:** مقایسه اجراها و آزمایش‌های Ablation.
6. **Data Audit:** آزمون نشتی اطلاعات و پاک‌سازی داده.
7. **Error Analysis:** ماتریس خطا؛ امکان ورود CSV برای تحلیل تک‌نمونه‌ای در همین صفحه.

## روش مرور لاگ‌ها

در صفحه **Experiment Graph & Logs**:

1. در قسمت **Choose a research track** یکی از چهار مسیر را انتخاب کن.
2. در گراف، روی دایره‌ها موس ببر تا خلاصه نتیجه ظاهر شود. رنگ قرمز به معنی تلاش شکست‌خورده و رنگ نارنجی به معنی نتیجه ناقص است.
3. جدول **What was logged at each step?** مرور سریع گام‌ها و منبع آن‌هاست.
4. در **Inspect one decision** یک گام را انتخاب کن. سمت چپ تغییرات و تنظیمات و سمت راست معیارهای نتیجه و محدودیت‌های آن را می‌بینی.
5. اگر آن گام آزمایش آموزشی باشد، نمودار AUC/F1/Loss مربوط به Epochهای همان اجرا در ادامه باز می‌شود.
6. برای رسیدن به متن منبع دقیقاً مطابق فایل اصلی، بخش **Read the exact original source** را باز کن. در انتهای صفحه هم همه فصل‌های گزارش اصلی در دسترس هستند.

**مثال:** مسیر `Alert-aware anticipation` → مرحله `Temporal Transformer + CNN B` نشان می‌دهد فقط ۸ Epoch از ۱۵ Epoch هدف ثبت شده است؛ AUC برابر 0.7493 و F1 برابر 0.7209 با Threshold انتخابی روی Validation محاسبه شده‌اند. نتیجه Test مستقل در گزارش موجود نیست؛ این مدل نباید به‌عنوان مدلی با Test F1 برابر 0.7209 معرفی شود.

## درباره «گراف» منتور

نوع دقیق نمودار در بازخورد مشخص نبوده است. در v3 **گراف تصمیم‌ها و وابستگی آزمایش‌ها** اضافه شده است، چون برای توضیح لاگ‌ها مناسب‌ترین انتخاب عملی بود. اگر منظور منتور **گراف معماری مدل** یا **Workflow داده تا پیش‌بینی** بوده، آن‌ها موضوع‌های متفاوتی هستند و می‌توان نسخه بعد را بر اساس خواسته دقیقش تغییر داد.

## وزن‌های واقعی دو مدل

در ZIP اولیه فایل‌های `*.pth` وجود نداشت. لذا بخش‌های تحلیل و گراف بلافاصله کار می‌کنند، ولی **پیش‌بینی زنده روی ویدیو هنوز به Checkpointهای معتبر نیاز دارد.** فایل‌ها در مسیر `models/detection.pth` و `models/anticipation.pth` باید با معماری درست هر نوت‌بوک تطابق داشته باشند. نام عمومی `best_mvit_collision.pth` در چند آزمایش تکرار شده است؛ هویت Checkpoint را پیش از جایگذاری بررسی کن.

دستور نصب نیازمندی‌های پیش‌بینی از نسخه قبلی تغییری نکرده است؛ جزئیات در `README.md` قبلی یا `requirements-inference.txt` وجود دارد.
